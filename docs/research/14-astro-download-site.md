# Astro download-site migration

Checked on 2026-10-25 while migrating the download page requested by the owner.

## Choice and dependency review

Astro renders the Korean and English pages to static HTML. Vue and Svelte were
considered; this page needs localized documents and a small release lookup, rather
than a client application runtime. The existing GitHub Pages host can serve Astro's
output directly. See the [official deployment guide](https://docs.astro.build/en/guides/deploy/github/).

The pinned package is Astro 7.4.2, MIT, maintained by withastro. The npm registry
reports publication at 2026-10-21T14:18:56.764Z, about 3.48 MB unpacked, and Node.js
22.23.4 or newer. This satisfies the workspace's three-day release-age rule and
Node.js 24 pin. The lockfile was generated by pnpm, not edited by hand.

Astro has a [public advisory history](https://github.com/withastro/astro/security/advisories).
The pinned dependency graph goes through the repository's OSV checks. This site
uses no server adapter, server actions, islands, or image optimization endpoint.
The unused optional `sharp` optimizer is not installed. Framework telemetry is
disabled in the package scripts and deployment workflow.

Zod reuses the existing workspace catalog version for untrusted JSON boundaries.
Vitest reuses the existing test-runner catalog version; test code is not imported
by the browser entry point. Both use the MIT license and introduce no new version
of a package already present in the workspace lockfile.

## Boundaries to preserve

- Korean and English implement one `Messages` contract. Language links work
  without JavaScript, at `/Lumen/` and `/Lumen/en/`.
- GitHub API responses, session-cache envelopes and client strings are validated
  with Zod. Bad release assets are dropped individually; a malformed release
  envelope produces the existing fallback state.
- Normalize asset URLs before checking the repository prefix. Otherwise encoded
  or ordinary dot segments can escape the intended repository path.
- Cache entries older than ten minutes or dated in the future are ignored.
- API strings reach the page through escaped markup or `textContent`, never
  `innerHTML`. Download URLs are constrained to the repository's release location.
- The browser request omits credentials and referrers and stops after eight seconds.
- Zod uses `jitless: true` before schema construction. Its eval-capability probe
  otherwise triggers a CSP violation even when the caught error falls back to
  ordinary validation. The pinned package documents this setting in its config
  type and checks it before probing; the browser fixtures verify no CSP events.
- Scripts and styles remain external, matching the existing CSP. Astro's
  [styling guide](https://docs.astro.build/en/guides/styling/) documents
  `inlineStylesheets: "never"` and `assetsInlineLimit: 0`.

## Verification and limitations

`just check` remains the entry point. TypeScript 7 checks the TypeScript modules,
`astro build` compiles the templates, and Biome's full HTML/Astro support checks
the complete templates. No lint rule is disabled to hide template imports.

The `.astro` templates are not semantically type-checked by `tsc`; the TypeScript
configuration explicitly includes the `.ts` modules. Keep reusable logic in those
typed modules. Browser fixture tests cover locale links, platform detection,
hostile release data, missing releases, rate limiting, malformed responses,
disabled JavaScript, narrow layouts and CSP.

The original page stays deployable while the components are added. The stylesheet
and icons move with Git renames and the original HTML references are updated,
including the absolute stylesheet link in the legacy 404 page. The workflow changes
to `apps/site/dist` only once the complete Astro page is ready; obsolete sources
can then be removed independently.
